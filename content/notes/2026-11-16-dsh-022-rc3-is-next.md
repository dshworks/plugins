---
title: dsh 0.2.2-rc.3 is on next, and a plugin can install and still not load
summary: npm's next tag points at dsh 0.2.2-rc.3, published 2026-11-13. latest is still rc.1. rc.3 is 1,574 commits after rc.1, and those commits rename or remove seven harness packages a plugin can import. dsh's install gate reads version ranges, not imports, so it admits a plugin that imports one of them, and dsh then skips that plugin at startup with a warning. We found 3 published plugins that do this. On one set of 11,611 manifests, rc.3 refuses 53 plugins that rc.1 installs, and admits 123 that rc.1 refuses. Our dsh-watch 0.2.3 still never arms its standing watches.
---

npm published `@deepseek-ai/dsh` 0.2.2-rc.2 on 2026-11-12 at 02:16 UTC and
0.2.2-rc.3 on 2026-11-13 at 08:05 UTC, both under the `next` tag. Both
[GitHub releases](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.3)
are marked prerelease. `latest`, what `npx @deepseek-ai/dsh` runs, is still
0.2.2-rc.1. To try rc.3, run `npx @deepseek-ai/dsh@next`.

## What rc.3 is

rc.2 is [1,568 commits after rc.1](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.2-rc.1...dsh-v0.2.2-rc.2).
rc.3 is [6 more](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.2-rc.2...dsh-v0.2.2-rc.3):
a CI cache, a Desktop restart fix, an experimental import of DeepSeek chat
exports as Sessions, and the version bump. rc.2 and rc.3 carry 143 upgrade
guides. rc.1 carries 98.

The install gate,
[plugin-compatibility.ts](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/packages/boot/app-boot/src/plugin-compatibility.ts),
is the same blob (2e4ca57) at rc.1, rc.2 and rc.3. So is profile.ts, which
sets the pnpm options every plugin install uses.

## Who is refused on rc.3

Measured on 2026-11-16, both versions judged the same `latest` manifests of
the same 11,611 packages:

- rc.1 refuses 1,609. rc.3 refuses 1,539.
- **53 install on rc.1 and are refused by rc.3**: 32 by an `engines.dsh`
  range and 21 by a dsh peer range.
- 123 go the other way. Every one of their ranges starts at 0.2.2-rc.2 or
  0.2.2-rc.3.

None of the 53 trips on anything rc.3 changed. Each range names versions and
stops before rc.3:

- 21 name 0.2.2-rc.1 alone.
- 30 list exact versions joined by `||`, and none of those lists has rc.3. 4
  of them added rc.2.
- 2 cap below rc.3, at `<0.2.2-rc.3` and `<=0.2.2-rc.2`.

The five of the 53 with the most npm downloads from 2026-10-16 to 2026-11-14
had between 6,537 and 17,547 each. All five are `||` lists. We ran five
packages through the real `dsh plugin add` of both versions, three of the 53
and two of the 123, and all ten verdicts matched the census.

Every package, the rule it tripped, its downloads, and the 123 are in
[/_data/notes/dsh-022-rc3-next.json](/_data/notes/dsh-022-rc3-next.json).
The front page's [refusal census](/#installs) re-measures every night.

This is what [the 0.2.1-rc.3 note](/notes/rc3-is-small-master-is-not) said:
an exact version, alone or in a list, is refused by every release it does not
name. Declare the range you have tested, not one prerelease.

## Installs, then does not load

The gate reads a plugin's version ranges. It does not read its imports. A
plugin's `@deepseek-ai/dsh-*` imports resolve to the copies that ship with
dsh, and rc.2 renamed or removed seven of those packages. Each is in the rc.1
install and missing from the rc.3 install:

- `@deepseek-ai/dsh-office-to-pdf` is now `@deepseek-ai/dsh-office-kit`, and
  `ctx.officeToPdf` is `ctx.officeKit`
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.2-alpha.3/office-kit-package/guide.md)).
- `@deepseek-ai/dsh-experimental-agent-team`,
  `dsh-experimental-tool-agent-team` and `dsh-experimental-client-ui-agent-team`
  are now `@deepseek-ai/dsh-agent-team`, `dsh-tool-agent-team` and
  `dsh-client-ui-agent-team`. `dsh-experimental-agent-team-profile` is retired;
  the base and Web bundles supply its plugins
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.1-rc.2/session-team-mode/guide.md)).
- `@deepseek-ai/dsh-deepseek-account-platform` and `dsh-api-account-controller`
  are removed. `@deepseek-ai/dsh-deepseek-account` is now the concrete account
  service and owns the `account` Remote
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.2-rc.1/account-remote-provider/guide.md)).

We measured what that does with a throwaway bundle whose entry imports
`@deepseek-ai/dsh-office-to-pdf` and whose `engines.dsh` admits both
versions:

- rc.1 installs it and loads it.
- rc.3 installs it too, and `dsh plugin add` exits 0. At startup it prints
  `dsh: warning: 1 entry did not activate` with `ERR_MODULE_NOT_FOUND`, then
  runs the Session without the plugin.

Then the published plugins. In the same 11,611 manifests, 10 declare one of
the seven packages as a peer. rc.3's gate admits 9 of them, and 3 of those 9
import a removed package at runtime from a file they ship. We installed one
of the three on rc.3. It installed, and at startup it did not activate, with
the same error.

In a sample of 1,000 published tarballs, every 11th package, none imported
these packages without declaring them. One of the 1,000 calls
`ctx.subagents.drainChildren`, which rc.2 removed
([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.1-rc.2/subagent-service-methods/guide.md)).

## Other changes a plugin can feel

All of these are in the rc.3 tag and not in rc.1.

- **Agent Teams uses the standard subagent tools.** The Team-specific
  creation, messaging, listing and interruption tools and their configuration
  keys are removed
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.1-rc.2/agent-team-subagents/guide.md)),
  and Team mode is off for new Sessions. `ctx.subagents` no longer has
  `drainChildren`, `listChildren` or `list`.
- **Office operations are tools.** `office_render`, `office_convert` and
  `office_recalculate` replace the `office-render`, `office-recalculate` and
  `office-export-pdf` skills. `DSH_BUNDLED_OFFICE_CLI`,
  `DSH_BUNDLED_OFFICE_NODE` and `DSH_BUNDLED_OFFICE_SKILLS` are gone, and
  `DSH_BUNDLED_PRIMARY_RUNTIME` is now `DSH_PRIMARY_RUNTIME`
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.2-alpha.3/office-operation-tools/guide.md)).
- **An update checks what it installed.** An update from the Plugins page is
  rolled back when it installs another package or version, a package with no
  bundle, or a bundle whose patches do not load
  ([operations.ts](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/packages/boot/plugin-manager/src/operations.ts#L513-L543)).
  A plugin installed from a Git commit can now be updated to another commit
  of the same repository directory. `BundleInfo.updatable` is replaced by
  `update`, which is `'registry'` or `'git'`
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.2-rc.1/plugin-update-method/guide.md)).
  `dsh plugin add` refuses the same packages it did. After a refusal it now
  also reinstalls the restored lockfile.
- **Client menus are anchored with CSS.** Client UI code must replace
  JavaScript panel positioning and Menu rectangle callbacks with CSS anchors
  ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/docs/upgrade-guide/v0.2.2-alpha.2/css-anchored-menus/guide.md)).
- **A bundle may name `wsl`** in `dsh.bundle.platforms`
  ([bundle-platform.ts](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.3/packages/boot/app-boot/src/bundle-platform.ts#L30-L33)).
  rc.1, which `latest` serves, does not know the value. Measured: `dsh plugin
  add` of a bundle declaring `["wsl"]` ends rc.1 with an uncaught error and a
  stack trace. On rc.3, on a Linux host that is not WSL, the same bundle gets
  a clean `bundle activation rejected`. A malformed value such as
  `["windows"]` still crashes rc.3's `plugin add`. 6 of the 11,131 published
  bundles declare platforms, all valid, and none names `wsl`.

## Custom plugin indexes

The registry's index at
[dsh.works/awesome-dsh-plugins/market/index.json](https://dsh.works/awesome-dsh-plugins/market/index.json)
passes rc.3's own index parser: 10,892 plugins and 88,857 versions, all from
npm. rc.3's parser also reads a `null` metadata field as absent.

## Our plugins

All five of ours install on rc.3 through the real `dsh plugin add`, none of
them puts a dsh package in the profile, and none imports a package rc.2
removed.

- **dsh-watch 0.2.3, the version on npm, is still broken on rc.3.** Its
  standing watches (`autoArm`) did not arm in 30 seconds, and it printed
  nothing about it. Under the build in
  [dsh-watch#12](https://github.com/dshworks/dsh-watch/pull/12) the probe
  watch started in 2 seconds. #12 is not published.
- dsh-meter 0.5.5, and the 0.5.6 build in
  [dsh-meter#38](https://github.com/dshworks/dsh-meter/pull/38), each counted
  a real headless `deepseek-flash` call: 1 request, 15,910 input tokens.
- dsh-ego-browser 0.1.4 and dsh-crew 0.2.4 answer on their web routes.
- dsh-solidworks 0.2.1 installs. We did not run it: this host has no
  SOLIDWORKS.

## What this cannot see

- The gate census reads manifests. The import counts read declared peers for
  every package, and code for a sample of 1,000. A plugin outside the sample
  that imports a removed package without declaring it is not counted.
- master carries 18 upgrade guides that rc.3 does not, the Python PTC removal
  among them. Those changes are in no release yet.
- Downloads are npm's counts, which include mirrors and CI.
- 58 names the registry lists are not served by npm and are not counted.
